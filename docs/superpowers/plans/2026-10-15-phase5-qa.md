# Phase 5 — Deploy + QA Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the live page launch-ready: real Brevo sending, a rate limit on `/api/lead`, a daily FX rebuild, the
Phase 4 deferred minors fixed, and a QA pass (Lighthouse, device emulation, links, no-JS, console) with a launch checklist.

**Architecture:** No new runtime services beyond Brevo (already decided). The rate limit is a Vercel WAF rule (no code).
The FX rebuild is a GitHub Actions cron that POSTs a Vercel Deploy Hook. Code changes are small: `track.ts` (two
fixes), `analytics.ts` + CSS (bar placement), a Brevo setup script with a schema test, one workflow file.

**Tech Stack:** Astro 7 static + Vercel function (Node 24, native `.ts`), Brevo API v3, Umami Cloud, Playwright,
`npx lighthouse`, `npx linkinator`, GitHub Actions.

**Spec:** `CLAUDE.md` (Phase 5), `docs/decisions.md` §6a, §11, §14 #10, §15 #16–17, §16; Phase 4 ledger in
`docs/ai-worklog.md` ("Phase 4 final review").

## Review Focus

1. **`PLAN_SENT_AT` created as a Brevo *date* attribute** → Brevo keeps only the day, the 24 h dedupe compares against
   midnight and resends early or never. Must be a *text* attribute; Task 4's schema test pins the types, the live
   double-submit proves it.
2. **Brevo blocks API calls from unknown IPs** (an account security option; Vercel functions have changing IPs) → every
   lead 502s. Verify the option in Task 4 and test with a real submit from the live URL, not from localhost.
3. **Shared mobile IPs (operator CGNAT)** → strangers share one IP and the rate limit 429s a real visitor. Limit set
   generously (10 / 10 min), the 429 copy tells them when to retry; Task 3.
4. **Brevo click tracking rewrites the `/plan` link** → `utm_source=email` could be lost and `magnet_opened` never fires.
   Task 4 clicks the real link from both inboxes and checks Umami Realtime.
5. **The scheduled run fails silently** (missing secret, hook deleted) → stale FX date. `curl -f` fails the job (GitHub
   e-mails the owner); Task 5 runs it once by hand and once on schedule.
